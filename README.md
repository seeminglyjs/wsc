# wsc

**windows system check** — 윈도우의 CPU·메모리·네트워크 사용량과 자원을 많이 먹는 프로세스를 터미널에서 바로 보는 모니터.
맥용 [msc](https://github.com/seeminglyjs/msc) 의 윈도우판이다.

- **어떤 프로세스가 어느 포트를 잡고 있는지 같이 보여준다.** `netstat -ano` 를 뒤져 PID 를 맞춰볼 필요 없다
- **같은 이름의 프로세스를 한 줄로 합쳐 보여준다.** 크롬·VS Code 처럼 여러 개 띄우는 프로그램이 다 합쳐 얼마나 먹는지 바로 보인다. `g` 로 하나씩 보기와 오간다
- **코어마다 따로 보여준다.** 전체 CPU 는 낮은데 느린 경우(코어 하나만 꽉 찬 경우)가 바로 보인다
- **창을 내려 둬도 보인다.** Windows Terminal 에서는 작업 표시줄 아이콘이 CPU 게이지가 되고(초록·노랑·빨강), 창 제목에 CPU·메모리 % 가 뜬다
- **최근 몇 분의 CPU 추이를 점자 글자 그래프로 그린다.** 막대와 숫자는 새 값으로 툭 바뀌지 않고 미끄러지듯 옮겨 간다
- **파일 하나, 설치 없음.** 파이썬 표준 라이브러리만 쓴다. `pip install` 필요 없음
- **관리자 권한 없이도 모든 프로세스와 포트가 보인다.** 작업 관리자와 같은 길로 읽기 때문이다
- 외부 명령(`tasklist`, `wmic`, `netstat`)을 띄우지 않고 윈도우 API 를 바로 부른다. 가볍고, 윈도우 표시 언어와 상관없이 똑같이 동작한다

## 준비 — 파이썬

맥과 달리 윈도우에는 파이썬이 기본으로 없다. 3.8 이상이 필요하다.

```powershell
winget install Python.Python.3.12
```

또는 [python.org](https://www.python.org/downloads/windows/) 에서 받아 설치한다.
터미널에서 `python` 을 쳤을 때 마이크로소프트 스토어가 뜨면 아직 진짜 파이썬이 없는 것이다.

## 설치

### 방법 1 — 받아서 바로 실행

```powershell
git clone https://github.com/seeminglyjs/wsc.git
py wsc\wsc.py
```

### 방법 2 — 어디서나 `wsc` 명령으로 쓰기

받은 폴더를 사용자 PATH 에 넣는다. 폴더 안의 `wsc.cmd` 가 `wsc.py` 를 대신 띄워준다.

```powershell
git clone https://github.com/seeminglyjs/wsc.git $HOME\wsc
$p = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$p;$HOME\wsc", "User")
```

터미널을 새로 열면 아무 데서나:

```powershell
wsc
```

`setx PATH ...` 는 쓰지 마라. 1024자 넘는 PATH 를 잘라버린다.

### 방법 3 — 파일 하나만 내려받기

```powershell
curl.exe -fsSL https://raw.githubusercontent.com/seeminglyjs/wsc/main/wsc.py -o wsc.py; py wsc.py
```

## 사용법

```powershell
wsc                 # 기본. 2초마다 갱신, CPU 사용률 순
wsc -i 1            # 1초마다 갱신
wsc -s mem          # 메모리 많이 먹는 순으로 시작
wsc -i 0.5 -s mem   # 같이 쓰기
```

### 옵션

| 옵션 | 뜻 | 기본값 |
| --- | --- | --- |
| `-i`, `--interval` | 화면 갱신 주기(초). 0.5 ~ 10 | `2.0` |
| `-s`, `--sort` | 정렬 기준 (`cpu` 또는 `mem`) | `cpu` |
| `--ascii` | 막대·기호를 영문 기호(`#` `.`)로 그린다 | 자동 |
| `--unicode` | 막대·기호를 늘 유니코드(`█` `·`)로 그린다 | 자동 |
| `-v`, `--version` | 설치된 버전 보기 | |
| `--check-update` | 새 버전이 있는지 확인만 | |
| `-u`, `--update` | 최신 버전으로 갱신 | |
| `--no-check` | 실행할 때 새 버전 확인 건너뛰기 | |
| `--no-logo` | 시작 로고 건너뛰기 | |
| `-h`, `--help` | 도움말 | |

켜면 1초쯤 `WSC` 로고가 뜬다. 그사이 첫 측정을 끝내 두므로, 로고가 걷히면 첫 화면부터 CPU 값이 나온다.
아무 키나 누르면 바로 넘어가고, 늘 건너뛰려면 `--no-logo` 를 준다. `wsc --version` 에도 같은 로고가 나온다.

### 실행 중 키

| 키 | 동작 |
| --- | --- |
| `↑` `↓` | 프로세스 고르기 (고른 줄은 파란 바탕에 흰 글씨로 표시) |
| `PgUp` `PgDn` | 한 화면씩 건너뛰며 고르기 |
| `Home` `End` | 맨 위·맨 아래로 |
| `k` | 고른 프로세스 종료시키기 (확인을 한 번 더 받는다) |
| `c` | CPU 사용률 순으로 정렬 (표 머리의 `CPU%▼` 가 지금 기준) |
| `m` | 메모리 사용량 순으로 정렬 |
| `g` | 같은 이름끼리 합쳐 보기 ↔ 하나씩 보기 (처음엔 합쳐 보기) |
| `+` | 갱신 주기 0.5초 늘리기 (최대 10초) |
| `-` | 갱신 주기 0.5초 줄이기 (최소 0.5초) |
| `Esc` | 고른 것 풀기 / 확인 취소 |
| `q` | 나가기 (`Ctrl-C` 도 됨) |

고른 줄은 줄 번호가 아니라 PID 를 따라간다. 순위가 바뀌면 고른 줄도 표 안에서 같이 움직인다.

### 같은 이름끼리 합쳐 보기

크롬은 탭·확장마다 프로세스를 따로 띄워서 `chrome.exe` 가 수십 개 뜬다. 하나하나는 작아 보여도 합치면
가장 많이 먹는 프로그램일 수 있다. 그래서 wsc 는 처음부터 **같은 이름의 프로세스를 한 줄로 합쳐** 보여준다.
CPU%·메모리는 더한 값이고, 포트는 다 모아 적는다.

```
     PID    CPU%▼    메모리  포트       이름  같은 이름끼리 합침 · ×N = 합친 개수
     ×27     11.2     3.4GB             claude.exe
     ×11      2.0     1.0GB             chrome.exe
       4      0.7      12KB  :139+2     System
```

PID 칸의 `×27` 은 27개를 합쳤다는 뜻이다. 하나뿐인 건 PID 를 그대로 적는다.

`g` 를 누르면 하나씩 보기로 바뀌고, 다시 누르면 합쳐 보기로 돌아온다. 조작 줄의 `g` 옆에는 지금 누르면
무엇이 되는지가 적혀 있다(`하나씩 보기` / `같은 이름 합치기`). 고른 줄은 합칠 때 그 이름의 줄로, 펼칠 때
그 이름 중 가장 큰 프로세스로 옮겨 간다.

합친 줄은 `k` 로 종료할 수 없다. 같은 이름의 딴 프로그램까지 한꺼번에 꺼질 수 있어서다. `g` 로 펼친 뒤
하나씩 고른다. 하나뿐인 줄은 합쳐 보기에서도 바로 끌 수 있다.

## 어느 터미널에서 쓰나

**Windows Terminal 을 권한다.** 윈도우 11 에서는 기본 터미널이라 PowerShell·명령 프롬프트를 열면 대개 그 안에서 뜬다.
VS Code 의 터미널도 된다.

옛 콘솔 창(conhost)을 한국어·일본어·중국어 코드 페이지로 쓰면 `█` `·` `…` 같은 글자를 두 칸으로 그려서
표가 통째로 어긋난다. wsc 는 이걸 알아채고 그 경우에만 영문 기호로 바꿔 그린다. 판단이 틀렸으면
`--ascii` 나 `--unicode` 로 직접 정한다.

**작업 표시줄 아이콘의 CPU 게이지는 Windows Terminal 에서만 보인다.** 아이콘에 진행 막대를 채우고
CPU 60% 를 넘으면 노랑, 85% 를 넘으면 빨강으로 바뀐다. 나가면 걷힌다. 창 제목의 `wsc · CPU 20% · 메모리 28%` 는
어느 터미널에서나 뜨고, 나갈 때 원래 제목으로 돌려놓는다.

옛 콘솔 창을 영문 기호 모드로 쓸 때는 추이 그래프와 막대가 미끄러지는 연출을 끈다. 점자 글자가 두 칸으로
그려질 수 있고, 한 장 그리는 게 느려서 오히려 버벅이기 때문이다.

Git Bash 의 기본 창(mintty)은 파이썬이 콘솔로 알아보지 못해 한 번 찍고 끝나는 기록 모드로 돈다.
Git Bash 를 Windows Terminal 안에서 열면 정상으로 돈다.

## 프로세스 종료시키기

멈춘 프로그램이나 자원을 과하게 먹는 프로세스를 목록에서 바로 끝낼 수 있다.

1. `↑` `↓` 로 대상을 고른다
2. `k` 를 누른다
3. 아래에 빨간 확인 막대가 뜬다 — `y` 창 닫기, `f` 강제 종료, 그 밖의 키는 취소

```
 종료 확인: chrome.exe (PID 34040)                           y  창 닫기   f  강제   n  취소
```

**`y` 를 먼저 써라.** 그 프로그램의 창에 닫기 요청을 보낸다. 창 오른쪽 위 X 를 누른 것과 같아서,
프로그램이 "저장할까요?" 를 묻고 스스로 정리한 뒤 닫힌다.
`f` 는 강제 종료라 프로그램이 저항할 수 없지만, **저장 안 한 작업은 그대로 날아간다.**

맥의 msc 와 다른 점이 하나 있다. 윈도우에는 "정리하고 끝내라" 는 신호(SIGTERM)가 없다.
그래서 **창이 없는 프로세스**(백그라운드 서비스, 다른 터미널에서 도는 `node` 같은 콘솔 프로그램)에는
`y` 가 통하지 않고, 그렇다고 알려준다. 그런 건 `f` 로 끝내거나, 그 프로그램이 도는 터미널에서 `Ctrl-C` 를 누른다.

안전장치:

| 상황 | 동작 |
| --- | --- |
| `System` `Registry` `smss.exe` `csrss.exe` `wininit.exe` `winlogon.exe` `services.exe` `lsass.exe` 등 | 종료 막음. 죽이면 블루스크린이 뜨거나 곧바로 재시동된다 |
| PID 0, 4 | 종료 막음 |
| wsc 자기 자신 | 종료 막음 (`q` 로 나가라고 안내) |
| 확인을 기다리는 사이 끝나고 같은 PID 로 딴 게 뜬 경우 | 엉뚱한 걸 죽이지 않고 이미 없다고 알려준다 |
| 다른 사용자·시스템 소유 프로세스 | 시도는 하되 권한이 없다고 알려준다 |
| 이미 없는 프로세스 | 이미 없다고 알려준다 |

윈도우는 끝난 프로세스의 PID 를 금방 다시 쓴다. 그래서 wsc 는 PID 만 보지 않고 프로세스가 태어난 시각까지
맞춰본 뒤에 끝낸다.

확인 막대가 떠 있는 동안에는 다른 키가 전부 막힌다. 실수로 정렬 키를 눌러 진행되는 일이 없다.
결과는 표 아래 알림 줄에 5초간 뜨고, 종료가 성공하면 목록을 즉시 다시 읽는다.

시스템 소유 프로세스까지 끝내야 하면 시작 메뉴에서 터미널을 **관리자 권한으로 실행**한 뒤 wsc 를 띄운다.
그러면 제목 줄 오른쪽에 노랗게 `관리자` 가 뜬다. 잘못 고르면 기기가 멈출 수 있다.

## 버전 확인과 갱신

```powershell
wsc --version         # 설치된 버전
wsc --check-update    # 새 버전 있는지 확인만
wsc --update          # 최신 버전으로 갱신
```

실행하면 하루에 한 번 조용히 새 버전을 확인해서, 있으면 조작키 줄 바로 위 알림 줄에
`새 버전 1.6.0 나옴` 이 뜬다. 확인 결과는 `%LOCALAPPDATA%\wsc\version` 에 담아둔다.
확인은 별도 흐름에서 돌아가 화면이 뜨는 걸 막지 않고, 인터넷이 안 되면 아무 말 없이 넘어간다.

`--update` 는 깃허브의 최신 파일을 받아 지금 실행 중인 파일을 덮어쓴다. 이때:

- 받은 파일에 **문법 오류가 있으면 덮어쓰지 않는다** (망가진 파일로 바뀌어 아예 안 열리는 걸 막는다)
- 서버 쪽 버전이 더 **낮거나 버전 표시가 없으면 덮어쓰지 않는다**
- 바꾸기 전 파일은 `wsc.py.bak` 으로 남긴다
- 임시 파일에 받은 뒤 한 번에 바꿔치기해서, 도중에 끊겨도 원본이 안 깨진다

`C:\Program Files` 처럼 권한이 필요한 곳에 두었다면 관리자 권한 터미널에서 `wsc --update` 를 한다.
`git clone` 으로 받아 쓰는 중이면 `git pull` 도 똑같이 동작한다.

새 버전을 올린 직후에는 최대 5분간 예전 버전이 보일 수 있다. 깃허브가 파일을 5분씩 담아두기
때문이고, 잠시 뒤 다시 하면 된다.

## 화면 읽는 법

윗칸 여섯 줄과 추이 그래프, 제목 줄의 메모리 배지가 기기 전체 상태, 아랫칸 표가 프로세스별 사용량이다.

| 항목 | 뜻 | 좋고 나쁨 판단 |
| --- | --- | --- |
| CPU | 전체 코어를 합쳐 몇 % 쓰는지. 작업 관리자의 CPU 값과 같다 | 60% 넘으면 노랑, 85% 넘으면 빨강. 막대는 차오를수록 청록 → 초록 → 노랑 → 빨강으로 번진다 |
| CPU 추이 | 네트워크 줄 아래의 점자 글자 그래프. 오른쪽 끝이 지금이고, 왼쪽 아래 숫자가 몇 초(분)치인지다. 한 칸에 갱신 두 번이 들어간다. 눈금은 0~100% 고정이고, 위로 갈수록 노랑·빨강으로 칠한다 | 방금 튄 건지 계속 높은 건지 가른다. 창이 27줄보다 낮으면 그래프 대신 CPU 줄 끝에 `▁▂▃▅▇` 로 최근 20번만 보인다 |
| `N%는 표에 없음` | CPU 값 중 아래 표의 어느 프로세스에도 안 잡힌 몫. 10%p 넘을 때만 노랗게 뜬다 | 뜨면 표를 뒤져도 범인이 없다. 아래 설명 참고 |
| 코어 | 코어마다 한 칸. 높이(`▁`~`█`)와 색이 그 코어의 사용률이다 | 전체 CPU 는 낮은데 한 칸만 계속 꽉 차 있으면 한 스레드로만 도는 프로그램이나 무한 루프다. 잠깐 튀는 건 흔하다 |
| 메모리 | 사용 중 / 전체. 작업 관리자 '성능' 탭의 사용 중과 같다. 막대 뒤에 캐시를 흐린 파랑으로 잇는다 | 같은 기준. 막대가 길어 보여도 파란 데까지는 여유다 |
| 압축 | 메모리가 모자라 눌러 담아둔 양 (`Memory Compression` 프로세스) | 몇 GB 쌓이면 메모리 부족 신호 |
| 캐시 | 파일을 읽어 담아둔 메모리. 필요하면 바로 내준다. 글자색이 메모리 막대의 파란 몫과 같다 | 커도 괜찮다. 오히려 정상 |
| 커밋 | 프로그램들이 "쓰겠다" 고 받아간 메모리 총량 / 한계 | 한계에 닿으면 새 프로그램이 안 열린다. 90% 넘으면 경고 |
| 페이지 | 페이지 파일(맥의 스왑) 사용량. 메모리가 모자라 디스크로 밀어낸 양 | 1GB 넘으면 노랑, 3GB 넘으면 빨강. 렉의 주범 |
| 메모리 배지 | 제목 줄 시계 옆. 메모리 사용률과 커밋 비율로 wsc 가 판단한 부족 정도(압박) | `여유` → `주의` → `위험`. `주의` 부터 어느 값이 넘었는지와 할 일이 메모리 줄 옆에 뜬다 |
| 네트워크 | 지금 받는(`↓`)·보내는(`↑`) 속도. 막대도 반으로 갈라 왼쪽 파랑이 받기, 오른쪽 보라가 보내기다. 영문 기호 모드에서는 `in`·`out` 으로 적는다 | 85% 넘으면 회선이 가득 찼다고 경고. 아래 설명 참고 |

맥에 있던 **부하 평균**은 윈도우에 없는 값이라 그 자리에 프로세스·스레드 수를 둔다.
창이 좁으면 회색 정보를 스레드 → 프로세스 → 코어 수, 캐시 → 압축 순으로 하나씩 뺀다. 경고 문구는 빼지 않는다.
**메모리 배지(압박)**도 맥은 커널이 직접 알려주지만 윈도우는 그런 값이 없어서, 메모리 사용률 85%·커밋 85% 를 넘으면
`주의`, 95% 를 넘으면 `위험` 으로 wsc 가 판단한다.

**CPU 가 튀었는데 표에 범인이 없으면 CPU 줄의 `N%는 표에 없음` 을 본다.**

```
 CPU      ━━━━━━━━━━━━╸───────────────      45.0%              17%는 표에 없음  (잠깐 뜬 프로세스·드라이버·VM 몫)
```

위 예시는 "CPU 를 45% 쓰는데, 그중 17% 는 아래 표의 어느 프로세스를 더해도 안 나온다" 는 뜻이다.
표의 CPU% 를 다 더하면 28% 쯤밖에 안 된다. 프로세스별 CPU 는 직전 갱신 때도 있던 프로세스끼리
비교해서 구하기 때문에, 다음 것들은 위의 CPU 값에는 들어가도 표에는 안 나온다.

- **잠깐 뜬 프로세스** — 갱신 사이(기본 2초)에 생겼다가 끝난 것. 빌드 도구, 스크립트, 백신 검사가 흔히 이렇다
- **드라이버** — 장치의 인터럽트·DPC 처리 시간. 어떤 프로세스에도 매기지 않는다
- **VM** — WSL2·Docker 같은 가상 머신이 쓰는 몫. 일부만 프로세스에 잡힌다

이게 크게 뜨면 표를 더 뒤지지 말고, 빌드·스크립트가 반복해서 돌고 있지 않은지, WSL·Docker 가 바쁜지부터 본다.
평소에도 몇 %p 는 이렇게 남아서 10%p 를 넘을 때만 띄운다. 창이 좁으면 괄호 속 원인 설명을 먼저 빼고,
그래도 좁으면 숫자만 남긴다.

**네트워크 줄은 기기 전체의 송수신 속도다.** 실제 랜카드·와이파이만 더한다. WSL·Hyper-V 의 가상 어댑터와
방화벽 필터는 같은 트래픽을 한 번 더 세게 되므로 뺀다. 옆에 장치 이름과 회선 속도를 적는다.

막대는 반으로 갈라 `↓` 받기(파랑)와 `↑` 보내기(보라)를 따로 그린다. 옆의 속도 글자도 같은 색이다.
길이는 회선 속도 대비를 **로그 눈금**으로 잰다. 그냥 나누면 1Gbps 회선에서 수십 KB/s 는 0.01% 라 평소엔
늘 비어 보이기 때문이다. 대략 1KB/s 면 비어 있고, 1MB/s 면 절반쯤, 회선을 꽉 채우면 끝까지 찬다.
'회선이 거의 가득 참' 경고는 눈금과 상관없이 실제 비율(85%)로 판단한다.

- **회선 속도가 생각보다 낮으면 케이블·포트를 의심한다.** 기가 인터넷인데 `회선 100Mbps` 로 뜨면
  랜선(Cat5 이하)이나 공유기 포트 때문에 100Mbps 로 붙은 것이다
- 와이파이의 회선 속도는 무선 연결 속도라 실제로 나오는 속도는 그 절반쯤이다
- 프로세스별 네트워크 사용량은 없다. 윈도우는 그 값을 관리자 권한(ETW)으로만 내준다.
  어떤 프로그램인지 봐야 하면 작업 관리자 '성능' 탭 아래의 '리소스 모니터 열기' → 네트워크 탭을 쓴다

**메모리가 느려질 때는 사용량보다 페이지와 커밋을 먼저 본다.** 사용량이 꽉 차 보여도 캐시가 크면
정상이고, 사용량에 여유가 있어 보여도 페이지 파일에 몇 GB 가 쌓였다면 그게 렉의 원인이다.

### CPU% 칸 — msc 와 다르다

**작업 관리자처럼 기기 전체 대비 % 다.** 모든 프로세스를 더하면 대개 위의 CPU 값이 된다
(크게 어긋나면 CPU 줄에 `N%는 표에 없음` 이 뜬다).
그래서 코어가 많은 기기에서는 숫자가 작게 나온다 — 8코어 기기에서 코어 하나를 꽉 채운 프로세스는 12.5%,
32코어면 3.1% 다. (맥의 msc 는 `top` 처럼 코어 하나 = 100% 다.)

그 대신 색은 코어 기준으로 매긴다. **코어 하나를 거의 다 쓰면 노랑**(무한 루프가 흔히 이렇다),
기기 전체의 절반을 넘으면 빨강, 1% 밑은 회색이다.

### 메모리 칸

작업 관리자 '프로세스' 탭의 메모리와 같은 값(개인 작업 집합)이다. 그 프로세스만 쓰고 있는 실제 메모리다.
100MB 밑은 회색, 1GB 밑은 기본 글자색, 그 위는 초록이다. 한 프로세스가 전체 메모리의 15% 를 넘으면 노랑,
21% 를 넘으면 빨강이다. 많이 먹는 것만 눈에 띄게 하려는 것이다.

### 포트 칸

그 프로세스가 **연결을 기다리며 잡고 있는 TCP 포트**다. 웹 서버·데이터베이스처럼 포트를 여는 것만 값이
찍히고, 나머지는 빈칸이다. 여러 개를 잡고 있으면 가장 작은 번호 하나만 적고 나머지 개수를 `+N` 으로 붙인다
(`:5432+1` = 5432 포함해 두 개).

- 맥과 달리 **관리자 권한 없이도 모든 프로세스의 포트가 보인다**
- `System`(PID 4) 에 `:139` `:445` 같은 게 붙는 건 윈도우 파일 공유라서 정상이다
- 창 너비가 76칸보다 좁으면 이름 칸을 지키려고 포트 칸을 접는다

## 기록용으로 쓰기

터미널이 아닌 곳으로 출력하면 색과 화면 제어 문자를 뺀 1회 출력으로 바뀐다.

```powershell
wsc > usage.txt                                   # 파일로 저장
wsc | Select-String chrome                        # 특정 앱만 보기
while ($true) { wsc >> log.txt }                  # 계속 기록
```

글자 인코딩은 콘솔 코드 페이지(한국어 윈도우면 cp949)를 따르고, 막대는 영문 기호로 바꿔 찍는다.
PowerShell 이 프로그램 출력을 그 코드 페이지로 읽어 들이기 때문에, 이렇게 해야 파일에서 한글이 안 깨진다.

## 동작 방식

프로세스 목록·CPU 시간·메모리는 `NtQuerySystemInformation` 한 번으로 읽는다. 작업 관리자와 Process Explorer 가
쓰는 방식이다. 프로세스를 하나씩 여는 방식은 권한이 없는 프로세스에서 막히지만, 이건 그런 게 없다.

프로세스별 CPU% 는 누적 CPU 시간을 두 번 재서 그 차이를 실제 흐른 시간과 코어 수로 나눈다.
전체 CPU 는 `GetSystemTimes` 의 유휴 시간 차이로 따로 잰다. 프로세스를 더하는 방식은 인터럽트 처리 시간을 놓치기 때문이다.
코어별 사용률은 `NtQuerySystemInformation` 의 코어별 누적 시간 차이로 같은 방식으로 잰다.

메모리는 `GlobalMemoryStatusEx` 와 `GetPerformanceInfo`, 페이지 파일은 `NtQuerySystemInformation`,
포트는 `GetExtendedTcpTable`, 네트워크는 `GetIfTable2` 의 장치별 누적 바이트 차이에서 읽는다. 전부 `ctypes` 로 부르므로 따로 설치할 게 없다.

키 입력은 `msvcrt` 로 받는다. 윈도우의 `select` 는 콘솔 입력을 기다리지 못해서 30ms 마다 살핀다.
CPU 는 거의 들지 않는다.
